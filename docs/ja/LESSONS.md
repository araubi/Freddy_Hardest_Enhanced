# Freddy Hardest Enhanced の教訓

[Español](../es/LECCIONES.md) · [English](../en/LESSONS.md) · **日本語**

スペクトラムから移植された MSX1 のゲームをカートリッジにする中で学んだことです。似たゲームにも役立ちます。

## 速度

1. **変化したセルの記録は、書き込むすべてのルーチンにフックを入れる。** 転送は今回か前回に記録したセルを送ります。フックしたゲームループ以外のフレーム（イントロ、メニュー）は全体を送ります。VRAM に直接書く処理があれば、全体転送を 2 回行います。記録は軽くないと（ラインの区間単位、行単位でまとめて）得た分を食いつぶします。
2. **決める前に測る。** 転送終了のラベル 1 か所のブレークポイントで各フレームの時間を測り、遅いフレームで PC をサンプリングします。こうして引っかかりの原因が見つかりました。待ちループを使う効果音です（爆発で 107 ms 止まっていました）。
3. **キークリックから PSG へ。** N サイクルのパルスは N/32 のトーン周期です。20 ms ごとのフレームに分け、各フレームで一番長く鳴るトーンを使います。拍は割り込みを使わず、VDP ステータスのビット 7 をポーリングして取ります。ポーズ中は PSG を黙らせます。
4. **リミッター**も同じポーリングで作ります。フレーム時間のばらつきが大きいゲームでは、VDP のフレームを数えるより毎秒のフレーム数で制限した方がテンポが安定します。

## VDP（TMS9918）

5. 表示中の VRAM アクセスは **29 サイクル以上**空けます。openMSX は標準では警告しません。リリース前に `too_fast_vram_access` と `vigila_vram.tcl` で確認します。
6. **SCREEN 2 で R3/R4 のマスクの技を使わない**（画面全体でパターンと色を 1 バンドだけにする技）。FPGA の VDP やエミュレーターの中にはマスクを無視するものがあります。3 つのバンドすべてに書きます。
7. 途中の状態が見えてしまう長い転送の間は**画面を消し**（R#1 = A0h）、正しくなってから表示します。
8. ゲームの文字ルーチンは 8 ドット単位の行でしか正しく描けないことがあります。テキストは 8 の倍数で動かします。

## スプライトのなかったゲームにスプライトを足す

9. **属性テーブルは、同じフレームのセルを送ったあと、VDP フレームの開始時に書く**（フレームフラグを読んだ直後）。早すぎたり走査の途中だったりすると、髪が体より先に動き、2 つのフレームが混ざって見えます。
10. **1 ラインに 5 枚以上**のときは、スプライト単位ではなくキャラクター単位でテーブルを回します。同じキャラクターが何フレームも続けて隠れないようにするためです。
11. **画面から画面へのスプライト消去。** 部屋制のゲームでは、ゲームのスプライトを**部屋に入る共通ルーチン**で消します。部屋を移る場所ごとに消すのではありません。そのルーチンへのジャンプをすべて探します（左右、エレベーターや階段、テレポート）。消すタイミングは**画面が変わり始める瞬間**です。部屋のルーチンはフラグを立てて記録済みのキャラクターを忘れ、転送はフラグを見たら最初の行を送る直前にテーブルを空にします。早く消すと、新しい部屋を作っている間、古い部屋がスプライトなしで残ります。遅く消すと、新しい部屋の上に古いスプライトが見えます。
12. テーブルを空にするときは、それを埋め直すもののカウンターも 0 にします。そうしないと、5 枚目のための回転で古いスプライトがまた書かれます。
13. ほかにも消去が必要な場面：ゲーム終了、GAME OVER、エンディングのテキスト、クレジット、メニュー。

## 色の塗り直し

14. スコアボードを独自の色で塗り直すと、ゲームが属性を変えずに **VRAM に直接描く**表示（ここでは弾丸バー）は塗り直しで消えてしまいます。その状態を属性にも保存するか、ゲームの変数から描き直します。

## カートリッジ

15. **パートごとに 64 KB のイメージ**：バンク 0 にメニュー、各パートは RAM イメージを 4 つのバンクに入れます。ページ 0 の空き領域に置いたコピー部が、A8h でスロットを切り替えながらページ 3、2、1、0 をコピーします。
16. 別のパートのルーチンを使うとき（パート 2 のクレジットでパート 1 の音楽）は、ページ 0 をコピーと入れ替え、終わったら元に戻します。
17. エンディングの間 RAM に置くモジュールは、ゲームに上書きされることがあります。使う前に ROM から読み直します。

## リバースエンジニアリングとテスト

18. **グラフィックはアセンブルしたイメージから取り出す。** プレイ中の RAM からではありません。イントロは画面バッファの領域にあり、ロゴの一部が欠けていました。
19. openMSX の `.omr` 録画はテスターの報告の再現に役立ちます。不具合の瞬間のセーブステートの方が、録画全体より役に立ちます。
20. 2 つのアセンブラー（pasmo と sjasmplus）で ROM がバイト単位で同一になるか確認します。sjasmplus では pasmo の `REPT … ENDM` は使えません。
21. **オリジナルを含めずに公開する**：リポジトリには自分の成果だけを入れ、残りは利用者のコピーからツールで取り出し、MD5 と SHA-1 で確認します。ゼロからのビルドで公開した ROM と同じものができる必要があります。
